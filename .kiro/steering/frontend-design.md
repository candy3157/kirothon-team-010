# Moviepato 프론트엔드 디자인 규칙

프론트 담당자와 디자인 피드백을 주고받으며 확정한 규칙이다. `frontend/` 파일을 고칠 때 항상 따른다.
기준 화면은 `frontend/src/`(React)이고, `frontend/demo/index.html`은 디자인 기록용이다.

## 수정 원칙

- **요청한 부분만 바꾼다.** 형태·배치·크기는 말하지 않았으면 그대로 둔다.
  - 예: "토글로 두지 마"는 접기만 없애라는 뜻이다. −/+ 형태를 버튼 묶음으로 바꾸지 않는다.
  - 예: "버튼을 둥근 네모로"는 모양만 바꾼다. 글자 크기를 키우지 않는다.
- 뺀 요소를 다시 넣지 않는다 (아래 "쓰지 않는 것").
- 화면을 직접 확인하지 못했으면 그렇다고 말한다.

## 색

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 바탕 | `#0b0b0b` | 전체 배경 |
| 면 | `#151515` / `#1e1e1e` | 카드, 입력칸 |
| 선 | `#2d2d2d` | 테두리, 구분선 |
| 빨강 | `#e11d2e` | 주요 버튼, 선택 상태, 순위, 이동 구간 |
| 어두운 빨강 | `#4a1219` 바탕 + `#ffd9dc` 글자 | 길찾기 버튼 |
| 반투명 빨강 | `rgba(225,29,46,.55)` | 지도 위 "이 지역 재검색" 버튼 (테두리 없음) |

- 검정과 빨강만 쓴다. 다른 강조색(초록, 파랑, 주황)은 쓰지 않는다.
- 그라데이션 배경, 빛 번짐, 그림자는 쓰지 않는다. "AI 사이트 같다"는 피드백을 받았다.

## 모양과 글자

- 글꼴은 Pretendard.
- 모서리: 버튼·입력칸 4px, 카드 6px, 상영회차 카드 12px.
- 아이콘은 이모지가 아니라 **손그림 SVG**(`frontend/src/components/Icon.tsx`)를 쓴다. 선을 일부러 살짝 삐뚤게 그린다.
- 순위는 `01`, `02`처럼 두 자리 빨간 숫자.

## 선택 상태

- 고른 버튼은 **빨강으로 채운다**: 이동수단, 출발 시각(지금 출발/시간 지정), 현재 위치 사용.
- "현재 위치 사용"은 평소 테두리 버튼이고, 현재 위치를 쓰는 중일 때만 빨강.
- 고른 상영회차는 빨간 테두리 + 빨간 시각. 꽉 채우지 않는다 (예매 버튼과 헷갈림).

## 애니메이션

세 가지(A 눌림 / B 퍼짐 / C 없음)를 데모로 비교해 **A · 눌림**으로 정했다. 코드는 `frontend/src/styles.css` 맨 아래 "누름 애니메이션" 묶음.

| 대상 | 누를 때 | 고를 때 |
|---|---|---|
| 버튼, 칩, 이동수단, 상영회차, 지도 버튼, 재검색 버튼 | `scale(0.96)`, 0.14초 | 배경·테두리·글자 색 0.22초 전환 |
| 영화관 카드, 영화 포스터 | `scale(0.985)` | — |
| 고른 이동수단 아이콘, 고른 회차 시각 | — | 한 번 3px 위로 뛰어오름(`hop`, 0.3–0.35초) |

- 움직임은 **눌렸다는 신호**로만 쓴다. 꾸미기용 반복 애니메이션은 넣지 않는다 (스크롤 안내 화살표도 거슬린다는 피드백으로 뺐다).
- 누른 자리에서 원이 퍼지는 효과(B), 배지 튀어나오기, 막대 자라기는 쓰지 않는다. 검정·빨강의 차분한 분위기를 해친다.
- 눌리지 않는 요소는 움직이지 않는다: `disabled` 버튼, 도착 불가 영화관(`.card.dim`).
- 새 버튼·카드를 만들면 위 묶음의 선택자 목록에 함께 넣는다.
- `prefers-reduced-motion: reduce`에서는 모든 전환·애니메이션을 끈다.

## 화면별 규칙

| 화면 | 규칙 |
|---|---|
| 스플래시 | 로고 `Moviepato.`(점만 빨강) + 슬로건 `Now showing, near you`. 1.5초 뒤 영화 선택으로. 누르면 바로 넘어감 |
| S01 영화 선택 | 상단 브랜드 바 없음. 제목 아래 설명 문구 없음. 포스터 위에 글자를 얹지 않음 |
| S02 출발 조건 | 하단 CTA는 "영화관 추천받기" 하나. 영화 변경은 위쪽 영화 칸의 "변경" 버튼 |
| S03 지도 | 지도 핀에는 영화관당 **가장 빠른 도착 가능 회차 하나**만. 정렬 버튼 없음 |
| S03 영화관 카드 | 아래 형태를 지킨다 |
| S04 상세 | 상영회차는 가로로 넘기는 둥근 카드. 이미 시작한 회차는 숨김. 하단은 길찾기(어두운 빨강) + 예매하기(빨강) |

영화관 카드 형태:

```
01  CGV 강남 [가장 빠른 관람] [가장 가까움]        상영시간
    0.4km                                          19:40
    19:12 ━━━━━━(이동, 빨강)━━━|━━━(대기, 회색)━━━ 19:40
          [🚇 14분 소요]               [19:26 도착]
```

- 이름 옆 빨간 배지: "가장 빠른 관람", "가장 가까움".
- 태그는 **소요 시간(빨강)**과 **도착 시각** 두 개만.
- 거리만 표시하고 브랜드명은 쓰지 않는다.

## 쓰지 않는 것

| 요소 | 이유 |
|---|---|
| 잔여 좌석 | 영화관 공개 API가 없어 가져올 수 없음 |
| 상영관 번호, 포맷(IMAX·4DX 등) | 디자인 결정으로 제외 |
| 검색 반경 설정, 지도의 반경 원 | 백엔드 원칙 "검색 반경 없음" |
| 정렬 버튼(가장 빨리/최단 이동/여유 있게) | 디자인 결정으로 제외. `sortBy: earliest` 고정 |
| 데모 상태 전환 패널 | 데모 전용 |
| 시작 화면의 큰 문구·일러스트·단계 안내 | 스플래시로 대체 |
| 스크롤 안내 화살표 | 거슬린다는 피드백 |

## API 연동 규칙

- 계약은 `docs/openapi.yaml`. 타입은 `frontend/src/api/types.ts`에 맞춰 둔다.
- 출발 시각은 **날짜 + 시간**으로 고른다(오늘부터 7일, `MAX_ADVANCE_DAYS`). `+09:00` ISO로 보낸다.
- 상영 전 도착 여유는 출발 조건 화면의 **−/+ 칸**(5분씩, 기본 10분)으로 정해 요청 `bufferMinutes`로 보낸다. 상세 화면에는 `meta.policy.bufferMinutes`(실제로 쓴 값)를 보여준다.
- **API에 없는 기능을 화면에서 바로 빼지 않는다.** 출발 날짜와 여유 시간은 API에 맞춰 뺐다가 둘 다 되살렸다. 먼저 팀에 "화면에서 뺄지, API를 고칠지" 묻는다.
- `not_showing`(상영 없음)과 `availability_unknown`(확인 불가), `unroutableCinemas`(경로 미확인)와 `unreachableCinemas`(도착 불가)를 서로 다른 화면으로 보여준다. 확인 못 한 것을 "없음"으로 표시하지 않는다.
